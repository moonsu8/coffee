# 로드맵: 커피 당번 → 안드로이드 마켓 출시용 서비스

지금까지 만든 커피 당번 앱을 안드로이드 마켓 출시용 서비스로 키운다.

## 현재 상태 (확인만 하고 바꾸지 말 것)
- 정적 PWA(Vite + React + TS), GitHub Pages 배포: https://moonsu8.github.io/coffee/
- 데이터는 기기 localStorage, 스키마 v4 (그룹, 요일 schedule, 템플릿 프리셋, 그룹별 테마)
- 순번(nextBuyer), 공평성(fairness), 주문(order) 로직은 순수 함수이고 테스트로 고정됨
- 섀도 백업, 마이그레이션, 미래 버전 거부, 최상위 members:[] 표식 장치가 있음

## 작업 원칙 (모든 단계 공통)
- 단계마다 계획 먼저 → 내 승인 → 구현. 나한테는 꼭 필요한 질문 1~2개만, 보고는 짧게
- 기존 순번·공평성·주문 로직과 테스트는 수정 없이 통과해야 함. 화면·테마도 최대한 재사용
- 확인 못 한 건 "확인 못 했다"고 정직하게 보고 (화면, 실제 기기, 실제 데이터)
- 커밋 작성자는 noreply 주소. 기능 하나 끝날 때마다 커밋, push는 단계별로 작게
- 스키마나 데이터 구조를 바꾸는 push 전에는 "총무 폰에서 JSON 내보내기 했어?"만 확인
- 롤백 금지, 옛 Actions 재실행 금지. 문제는 수정본을 앞으로만 배포
- 비밀값(서비스 키, 서명 키, 토큰)은 저장소·번들·내보내기 JSON에 절대 넣지 말 것.
  Supabase는 anon key만 클라이언트에, service_role key는 서버 함수에서만

## 개인정보 원칙 (A안으로 확정)
- 주민등록번호 등 고유식별정보, 카드·계좌 등 개인신용정보, 민감정보는 어떤 경로로도 수집·저장 금지
- 결제는 Google Play / PG사가 처리. 서버에는 구독 상태만 저장
- 멤버 이름(별명), 기록, 휴가, 금액, 주문은 서버에 평문 저장. 단 RLS로 그룹 소속자만 접근
- 멤버 입력칸에 "실명 대신 별명도 괜찮아요", 메모칸에 "주민번호·카드번호 등은 적지 마세요" 안내
- 탈퇴·그룹 삭제 시 서버 데이터 즉시 삭제. 만 14세 미만 가입 제한
- 저장 계층을 분리해서, 나중에 종단간 암호화(B안)로 바꿀 수 있게 설계

## 0단계: 선행 점검
- 구매 기록 추가 시트의 스크롤·저장 버튼 버그가 모든 바텀시트에서 해결돼 배포됐는지 확인.
  안 됐으면 이것부터 고쳐서 push (하단 고정 버튼, 100dvh, safe-area, 드래그는 손잡이에만)
- 출시용 도메인 연결 방안 제안: 커스텀 도메인 구매 시 GitHub Pages 연결 방법,
  또는 저장소를 private으로 바꾸고 Cloudflare Pages로 옮기는 방안의 장단점
  (App Links용 /.well-known/assetlinks.json이 도메인 최상위에 있어야 함)

## 1단계: Supabase 백엔드 + 권한 (그룹장 1명 쓰기, 그룹원 보기 전용)
- 서버 지역은 서울 리전 우선 검토
- 로그인: 그룹장은 카카오/구글 로그인, 그룹원은 익명 로그인 허용(나중에 계정 연결 가능)
- 테이블 초안: groups, group_members(role: owner|viewer), members, records, absences,
  orders, prices, invites, entitlements
- RLS: owner만 쓰기, 그룹 소속자만 읽기, 다른 그룹 접근 불가. RLS를 테스트로 검증하는 방법 포함
- 그룹장 기능: 기록·수정·휴가·멤버 관리·초대·그룹원 내보내기·그룹장 넘기기·그룹 삭제
- 그룹원: 당번·기록·통계·오늘의 주문 보기만. 쓰기 버튼 숨김 + 서버에서도 거절
- 실시간 반영(Supabase Realtime), 오프라인이면 마지막 데이터와 "마지막 업데이트 ○시 ○분" 표시
- 로그인 안 한 사용자는 지금처럼 기기 저장 유지. 공유를 켤 때만 "내 기기 데이터를 서버로 옮기기"
  (기존 마이그레이션·백업 구조 재사용, 옮기기 전 자동 백업)

### 1-F (1단계 마무리) 항목
- 그룹원 내보내기 · 그룹장 넘기기 · 그룹 삭제 · 계정 삭제의 앱 화면, 승인 옵션, 익명 로그인 CAPTCHA, 오프라인 쓰기 대기열
- **내보내진 그룹원이 늦게 알게 되는 문제**: Realtime의 DELETE는 RLS가 적용되지 않아 의존할 수 없고,
  내보내진 그룹원은 groups 변경 알림도 받지 못한다(소속이 사라졌으므로). 지금은 다음 갱신(화면 복귀 30초 간격·
  수동 새로고침·재연결)에서야 "그룹이 없어졌어요"가 뜬다. 1-F에서 삭제·내보내기 UI를 만들 때 즉시 알리는 방법
  (예: group_members를 소속 본인 행 기준으로 구독하거나, 갱신 주기·시점 조정)을 정하고 테스트로 고정한다.

### 1단계 이후 별도 작업: 서버 테스트 가볍게 만들기
- 배경: `test:rls`가 한 번에 익명 사용자를 약 75명 만든다(1-E·1-F에서 테스트가 늘어 이전 약 35명에서 두 배가 됨). 테스트 프로젝트의 로그인 한도(시간당·5분당 300)를 올려도, 연달아 돌리면 한도가 비워지고 채워지는 데 시간이 걸려 한 시간에 몇 번밖에 못 돌린다.
- 할 일(1단계 push 뒤, 한 번에 하나씩):
  1. **파일별 실행** 방법 정리: `npx vitest run -c vitest.rls.config.ts tests/rls/<파일>`, 변경한 영역만 돌리기. 전체 실행은 push 전 한 번.
  2. **파일 간 사용자 재사용**: 테스트 프로세스 사이에 사용자를 공유하는 방법(첫 실행에서 만든 사용자의 세션을 임시 파일에 저장해 재사용 등)을 검토. 소속 상태를 검사하는 테스트는 새 사용자가 필요하므로 의미가 바뀌지 않는 곳에만.
  3. 같은 파일 안 재사용 확대(`sharedUser`), 한 테스트에서 여러 검증 묶기.
  4. 실행 전에 남은 한도를 미리 알려 주는 사전 점검(익명 로그인 1회) 추가.
- 무리하게 바꾸지 않는다: 테스트의 의미(권한·소속 분리)가 약해지면 하지 않는다.

## 2단계: 초대 링크 흐름
- 초대 링크: https://<도메인>/join/<6자리 코드>, 만료·재발급·그룹장 승인 옵션
- 앱 있으면 앱에서 "○○ 그룹에 참여할까요?", 없으면 웹에서 바로 보기(설치 강요 금지).
  설치는 "당번 알림을 받으려면 앱 설치"처럼 이유가 있을 때만 권유
- 안드로이드 설치 후 첫 실행: Play Install Referrer로 초대 코드 자동 전달
- 아이폰(앱스토어 미출시, PWA만): "초대 코드 붙여넣기/입력" 칸
- 카카오톡 인앱 브라우저 감지 시 [앱에서 열기]/[브라우저로 열기] 안내 (기존 설치 안내 재사용)

## 3단계: 유료화 (그룹 단위 구독, 그룹원은 항상 무료)
- 무료: 그룹 1개, 그룹원 3명, 앱 열 때 갱신, 횟수 기준, 기본 템플릿·테마, 이번 달 통계
- 프로 그룹: 그룹 여러 개, 그룹원 무제한, 실시간, 아침 당번 푸시, 금액 기준·정산,
  전체 템플릿·테마, 전체 기간 통계·연말 리포트
- 가격 예시: 그룹당 월 2,900원 / 연 29,000원, 무료 체험 7~14일. 평생권은 서버 비용 없는 테마 팩에만
- 결제 경로: TWA 앱 안은 Google Play Billing만(웹 결제 버튼 숨김), 웹은 PG(토스페이먼츠 또는 포트원)
- 구독 상태는 entitlements 테이블, 웹훅을 서버 함수에서 검증해서만 갱신 (클라이언트 값 신뢰 금지)
- 구독 만료 시 데이터 삭제 금지, 읽기 전용 전환. 유료 안내는 제한에 걸리는 순간에만
- RevenueCat 사용 vs 직접 구현 비교
- 광고는 넣지 않음

## 4단계: 안드로이드(구글 플레이) 출시 준비 (애플 앱스토어는 하지 않음)
- Bubblewrap 또는 PWABuilder로 TWA 프로젝트(android/) 생성. 패키지명은 정하기 전에 나한테 확인
- 서명 키는 .gitignore, 보관·백업 방법 안내. Play 앱 서명 사용, assetlinks.json에 지문 반영
- 릴리스 AAB 빌드, 스토어 등록정보 문구·스크린샷 구성 제안
- public/privacy.html: 개인정보보호위원회 2026 처리방침 작성지침 구조로 초안.
  수집 항목(로그인 ID·이메일, 별명·당번 기록, 접속 기록, 구독 상태, 푸시 토큰),
  처리 위탁·국외 이전 표(Supabase 서버 지역, Google Play, PG사), 보관·파기, 이용자 권리,
  만 14세 미만 제한, 보호책임자(빈칸). 확실하지 않은 법적 문구에는 [확인 필요] 표시
- 앱 안과 웹에서 계정 삭제 기능 (구글 플레이 요구사항). **앱 안 경로는 1-F에서 구현됨**(설정 > 공유 그룹 > 계정 삭제, `delete_my_account`).
  공식 문서(Play Console 도움말 "Understand app account deletion requirements", 2026-11-22 확인)에서 확인한 요구사항:
  - 앱 안에서 계정을 만들 수 있으면 **앱 안 삭제 경로**와, 앱을 열지 않고도 삭제를 요청할 수 있는 **웹 링크**를 둔다.
  - 웹 링크는 **데이터 보안(Data safety) 양식에 적는다.** 작동하는 페이지여야 하고, 스토어에 표시된 앱/개발자 이름을 적어야 하며, 앱으로 되돌려 보내지 않고 삭제를 요청할 수 있어야 한다. 찾기 쉽게 둔다.
  - 계정 삭제 시 데이터 보안 양식에 "수집"으로 적은 **모든 사용자 데이터가 삭제 범위**다. 보안·사기 방지·법적 의무로 보관해야 하는 것은 예외가 될 수 있고 이유를 개인정보 처리방침 등에 알려야 한다.
  - 계정 없이 쓸 수 있는 기능이 있어도, 앱 안 어디서든 계정 생성이 가능하면 대상이다. 오프라인으로만 만들고 운영하는 계정, 비공개 앱·기업 기기관리 앱은 제외.
  - **[확인 필요]** 익명 로그인(그룹원) 계정도 앱 계정으로 보는 것이 안전하다(문서에 명시적 언급은 없음, 추정). 그래서 익명 계정도 앱 안에서 삭제할 수 있게 해 두었다(같은 화면).
  - **[확인 필요]** 문서에 적힌 시행 날짜(2023-12-07, 연장 2024-05-31)는 이미 지났고 이후 날짜는 문서에 없다. 출시 시점의 Play Console에서 현재 요구를 다시 확인한다.
  - **해야 할 일(4단계):** 도메인에 계정 삭제 요청 웹 페이지(예: `/account-deletion.html`)를 만든다. 앱 이름과 삭제 방법을 적고, 로그인(Google)해서 같은 삭제를 할 수 있게 하거나 개발자 연락처로 요청받는 절차를 적는다. 그 주소를 Data safety 양식에 넣는다. 삭제되는 데이터 목록(그룹·멤버·기록·휴가·금액·주문·별명·로그인 정보)과 보관하는 것(없음)을 처리방침과 맞춘다.
- 데이터 보안 양식에 적을 내용 정리
- 비공개 테스트(테스터 12명 이상, 14일 연속) 진행 방법과 테스터 안내문
- 매년 target API 상향 절차를 CLAUDE.md에 기록

## 나중에 할 것 (이번 로드맵에서는 구현하지 않음, 목록만)
- 프랜차이즈 메뉴: public/cafes/<id>.json, network-first 캐시, 가격·로고 제외,
  "목록에 없던 메뉴" 모음과 [메뉴 추가 요청 복사]
- 후원: 투네이션 링크(src/config.ts 상수, 값 없으면 숨김), 플레이 앱 안에서는 숨김
- 연말 "커피 랩드" 공유 카드와 굿즈, 카페 화이트라벨·제휴
- 기간 담당(주/월), 여러 명 동시 당번, 가중치 있는 일
- 종단간 암호화(B안) 전환

## 다듬을 것 (작은 개선 목록, 기능 단계와 별개)
- 시트 안 입력칸에서 Enter 키로 저장되지 않음: `SheetFooter`가 시트 아래 영역으로 옮겨 그려져서 폼의 submit 버튼이 폼과 연결되지 않는다. 시트 입력칸에 Enter 처리(키 이벤트로 저장 호출)를 넣거나 푸터 버튼을 `form` 속성으로 폼에 연결한다. (저장 실패는 아니고 Enter 미지원이다. 이전 배포부터 그대로)
