# 도메인 연결 안내서 (GitHub Pages + 커스텀 도메인)

> **연결 전에 총무 폰에서 JSON 내보내기 → 연결 후 새 주소에서 가져오기, 홈 화면 앱 재설치.**
>
> 커스텀 도메인을 설정하면 `moonsu8.github.io/coffee/`는 새 도메인으로 리디렉트된다.
> 데이터(localStorage)는 주소(origin)마다 따로라서, 리디렉트된 새 주소에서는 옛 데이터를 열 수 없다.
> 그래서 **연결하기 전에 반드시 내보내기**를 해 둔다. (이사 안내 화면은 만들지 않는다. 쓰는 사람이 총무 폰뿐이다.)

상태: **안내서와 변경 목록까지만.** 도메인이 정해지기 전에는 코드를 바꾸지 않는다.

## 사용자가 직접 하는 일 (순서)
1. 총무 폰에서 설정 > 데이터 > JSON 내보내기. 파일을 폰 밖(메일·클라우드)에도 하나 보관.
2. 도메인 구입 (등록 대행사 아무 곳).
3. DNS 설정 (도메인 이름 `example.app` 가정)
   - 루트(apex) 도메인: `A` 레코드 4개 → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - (선택) `www`: `CNAME` → `moonsu8.github.io`
   - 값은 GitHub 문서의 현재 값과 대조해서 입력한다 `[확인 필요]`
   - 이 도메인에는 다른 용도의 CNAME·A 레코드를 섞지 않는다.
4. 저장소 Settings → Pages → Custom domain에 도메인 입력 → 저장 → DNS 확인 통과 후 **Enforce HTTPS** 체크.
   (이 저장소는 Actions 배포라서 `CNAME` 파일이 아니라 이 설정 화면의 값이 기준이다.)
5. 도메인 연결이 끝나면 **개발 쪽 변경(아래 목록)을 배포**한다. (그 전에는 `base: './'` 상대 경로라 대부분 그대로 동작한다.)
6. 폰: 옛 홈 화면 앱 삭제 → 새 주소를 Chrome에서 열기 → 설정에서 JSON 가져오기 → 앱 설치(홈 화면 추가).
7. 가져온 기록이 맞는지 확인하고, 그 뒤에 옛 주소(`github.io`)는 쓰지 않는다.

## 개발 쪽 변경 목록 (도메인 확정 후 구현)
- **base 경로**: 지금은 `base: './'`. 도메인이 루트가 되면 `'/'`로 바꿀지, 상대 경로를 유지할지 결정한다. `/?join=` 방식이라 하위 경로 라우팅 문제는 없으므로 상대 경로 유지도 가능. 바꾼다면 `data.json`·아이콘·SW 경로를 함께 점검.
- **manifest**: `start_url`, `scope`, `id`(고정), 아이콘 경로. 도메인 루트 기준으로 정리. `id`는 한 번 정하면 바꾸지 않는다.
- **서비스 워커**: scope를 `/`로. `autoUpdate` 동작 유지. `/.well-known/*`은 SW 캐시·navigateFallback 대상에서 제외(항상 네트워크).
- **`.nojekyll`**: `public/.nojekyll` 추가. (Jekyll이 점(`.`)으로 시작하는 폴더인 `.well-known`을 무시하지 않게 한다. Actions 배포는 Jekyll을 쓰지 않지만 안전장치로 둔다.)
- **`public/.well-known/assetlinks.json` 자리**: 4단계 전까지는 빈 배열 `[]`로 두고, 4단계에서 패키지명과 Play 앱 서명 지문(SHA-256)을 넣는다. 도메인 **최상위** `/.well-known/assetlinks.json`, `Content-Type: application/json`이어야 한다.
- **초대 주소**: `https://<도메인>/?join=<8자리 코드>` (2단계). `404.html` 우회는 쓰지 않는다.
- **초대 안내문의 "앱 주소"** (주의): 코드에 주소가 고정돼 있지 않고, 그룹장이 앱을 연 주소(`location.origin + location.pathname`)가 그대로 들어간다. 그래서 도메인이 바뀌면 코드는 고칠 필요가 없지만, **그룹장은 새 도메인에서 앱을 열어 안내문을 복사해야 한다.** `github.io` 주소에서 복사한 안내문에는 옛 주소가 들어가고, 도메인이 바뀐 뒤에는 옛 주소로 참여한 그룹원의 로그인 세션이 새 주소로 이어지지 않는다(익명 세션은 도메인 단위). 도메인이 정해지면 이미 나눠 준 옛 안내문은 새로 만든 코드로 다시 보내 준다.
- **`index.html`/OG 메타**: 도메인 기준 canonical·공유 미리보기 주소.
- **옛 주소**: `github.io/coffee/`는 GitHub가 새 도메인으로 리디렉트한다. 별도 처리 없음.
- 배포는 `CLAUDE.md`의 배포 규칙(roll forward, 옛 Actions 재실행 금지)을 따른다. 데이터 구조 변경은 없다.

## App Links와 `/?join=코드` 방식
- App Links 검증(`assetlinks.json`)은 **호스트 단위**다. 경로나 쿼리는 상관없다.
- 앱(TWA)의 인텐트 필터는 `https` + 도메인 + `pathPrefix="/"` 정도로 걸고, **쿼리 파라미터로는 필터링하지 않는다.**
  그래서 `/?join=ABC123`도 `/join/ABC123`과 똑같이 앱으로 열린다. 열린 URL 전체(쿼리 포함)가 앱에 전달되므로 앱이 `join` 값을 읽으면 된다.
- 앱이 설치돼 있지 않으면 같은 주소가 브라우저에서 그대로 열리고 홈(`index.html`)이 `join` 쿼리를 읽는다. 서버 라우팅이 필요 없다(GitHub Pages에 맞음).
- 같은 호스트의 **모든** 링크가 앱으로 열리게 된다 (앱 설치 시). 초대 링크만 따로 구분할 수는 없다. 이 서비스에서는 문제가 아니다.
- 주의점 (확인 필요 `[확인 필요]`)
  - 카카오톡 인앱 브라우저에서 누른 링크는 App Links로 앱이 안 열리고 인앱 브라우저 안에서 열리는 경우가 많다. 그래서 2단계의 [앱에서 열기]/[브라우저로 열기] 안내가 필요하다.
  - 주소창에 직접 입력한 같은 도메인 이동은 앱으로 넘어가지 않는다. 링크 탭으로 열 때만 동작한다.
  - 쿼리가 있는 URL이 Play Install Referrer로 설치 후 첫 실행에 전달되는 흐름은 별도로 설계한다(2단계).
- 위는 Android 공식 동작에 대한 설명이며, **이 앱에서 실제 기기로는 확인하지 못했다.** 4단계 TWA가 만들어진 뒤 `adb shell pm get-app-links`와 실제 폰 링크 탭으로 검증한다.

## 도메인 이름 후보
앱 이름은 "커피 당번"이지만, 커피 말고 청소·발표·산책까지 돌아가며 하는 일 전반으로 넓어졌다. 이름을 넓게 잡을지 커피로 둘지에 따라 갈린다.

| 후보 | 도메인 예 | 비고 |
|---|---|---|
| 커피당번 (영문) | `coffeeduty.app` / `coffeeduty.kr` | 지금 이름 그대로. 커피 한정 느낌 |
| 당번 (한글 로마자) | `dangbun.app` / `dangbun.kr` | 짧고 범용적. 커피 외 템플릿에도 어울림 |
| 돌아가며 | `dolagamyeo.app` | 의미는 좋으나 길고 철자가 어려움 |
| 오늘 당번 | `todaysduty.app` / `ourturn.app` | 영어권도 이해하기 쉬움 |
| 차례 | `charye.app` | 짧지만 발음·철자가 낯섦 |

- 모두 **등록 가능 여부와 가격은 확인하지 못했다.** 구입 전에 등록 대행사에서 조회해야 한다.
- `.app`은 HTTPS가 필수이며 GitHub Pages의 HTTPS와 잘 맞는다. `.kr`은 한국 사용자에게 신뢰감이 있지만 연 비용과 등록 조건이 `.app`과 다를 수 있다 `[확인 필요]`.
- 스토어 앱 이름과 도메인이 달라도 문제는 없다. 다만 개인정보처리방침 주소로 쓰이므로 오래 쓸 이름으로 고른다.
